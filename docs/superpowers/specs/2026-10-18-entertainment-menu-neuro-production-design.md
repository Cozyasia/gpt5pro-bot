# Раздел «Развлечения» и продукт «Нейро Продакшен»

**Дата:** 2026-10-18  
**Статус:** на согласовании владельца продукта  
**Ветка:** `feature/entertainment-menu-neuro-production`  
**База:** `main@5a7480e05052e4a4f5cb8e64715ebaf945083304`

## 1. Решение

Сохраняем действующее корневое меню бота без переименований и перестановок. Перестраиваем только внутреннюю навигацию раздела `🔥 Развлечения`.

Главный принцип: пользователь сначала выбирает желаемый результат, а не нейросеть. Выбор конкретной модели и технических параметров остаётся доступен в `🎛 Режим режиссёра` и `🧠 Выбрать модель`.

Название `Нейро Продакшен` используется как премиальный производственный раздел. Названия `Автостудия` и `Создать видео по идее` не используются.

## 2. Цели

1. Сделать раздел понятным без знания названий нейросетей.
2. Превратить существующие генераторы в готовые коммерческие продукты.
3. Сохранить прямой доступ к моделям для опытных пользователей.
4. Убрать дублирующие кнопки и конкурирующие обработчики меню.
5. Исключить отрицательный баланс пользователя и убыточный запуск задания.
6. Не ломать существующие команды, callback-кнопки, ссылки и незавершённые диалоги.
7. Подготовить структуру к Telegram Mini App и сайту без второго каталога услуг.

## 3. Что не меняем

Корневое меню остаётся таким, как сейчас:

## 5. «Нейро Продакшен»

Это не перечень моделей, а набор результатов, за которые пользователь готов платить.

```text
🎬 Нейро Продакшен
├── 🛍 Товар → рекламный ролик
├── 📱 UGC-реклама
├── 🏠 Реклама недвижимости
├── 👤 Экспертное видео
├── 💎 Брендовый ролик
├── 📦 Серия Reels / Shorts
├── 🌍 Перевести и озвучить видео
├── 🧪 3 версии рекламы
├── 🤝 Индивидуальный проект
├── 🎛 Режим режиссёра
└── ⬅️ Назад
```

### 5.1. Общий мастер создания

Каждый готовый продукт использует короткий мастер:

1. Что рекламируем или о чём ролик.
2. Материалы: фото, видео, логотип, ссылка или текст.
3. Площадка: Reels, Shorts, TikTok, Stories, Telegram или универсальный формат.
4. Цель и аудитория.
5. Стиль/тон из 3–5 понятных вариантов.
6. Длительность и формат кадра.
7. Предпросмотр структуры, срок, цена и состав результата.
8. Явное подтверждение запуска и резервирование кредитов.
9. Статусы производства и выдача результата.
10. Действия после выдачи: `Повторить`, `Сделать вариант`, `Изменить текст`, `Улучшить`.

Пользователь может написать или надиктовать исходную идею. GPT превращает её в бриф и задаёт только недостающие вопросы.

### 5.2. Состав продуктов

| Продукт | Что получает пользователь | Базовый маршрут |
|---|---|---|
| Товар → рекламный ролик | сценарий, кадры, рекламное видео, текст публикации | изображение товара → сценарий → video engine → опциональная музыка |
| UGC-реклама | нативный вертикальный ролик с хуком, демонстрацией и CTA | бриф/товар → UGC-сценарий → человек/аватар или видеогенерация |
| Реклама недвижимости | вертикальная презентация объекта с подписями и озвучкой | фото/видео объекта → структура → монтаж/генерация → voiceover |
| Экспертное видео | говорящий эксперт или аватар, субтитры, CTA | фото/видео + текст → avatar/lip-sync → монтаж |
| Брендовый ролик | ролик с визуальным стилем, логотипом и музыкой | бренд-бриф → storyboard → video engine → финальная сборка |
| Серия Reels / Shorts | 3–10 связанных роликов с общей рубрикой | одна тема → пакет сценариев → пакет генераций |
| Перевести и озвучить видео | новая языковая версия с сохранением смысла и тайминга | транскрипция → перевод → дубляж/lip-sync → сборка |
| 3 версии рекламы | три разных хука/тона для теста одной идеи | один бриф → три сценарных варианта → три результата |
| Индивидуальный проект | сбор брифа и передача менеджеру без обещания автоматической цены | форма → оценка → ручное подтверждение |
| Режим режиссёра | ручной выбор модели, промпта, длительности, формата и дополнительных параметров | существующие прямые генераторы |

`Перевести и озвучить видео` включается как полноценный платный продукт только после подключения и проверки соответствующего endpoint. До этого кнопка помечается `Скоро` и не принимает оплату.

## 6. «В тренде»

Раздел состоит из быстро понятных шаблонов. Он должен обновляться без изменения основного роутинга через конфигурационный каталог рецептов.

```text
🔥 В тренде
├── ✨ Фото оживает
├── 🗣 Фото говорит
├── 💃 Фото танцует
├── 🎞 Я в кино
├── ⭐ Селфи со звездой
├── 🎁 Видео-поздравление
├── ↔️ До / После
├── ✈️ Travel Reel
├── 👗 Сменить образ
└── ⬅️ Назад
```

`Фото поёт` не выводится в массовое меню, пока текущий lip-sync сценарий не пройдёт отдельную проверку качества. После проверки он добавляется как `🎤 Фото поёт · Beta` с предупреждением о допустимых исходных фото.

Каждый шаблон показывает короткий пример, требования к исходнику и итоговую цену до списания. Видеопримеры хранятся как Telegram `file_id` с резервным URL/файлом, чтобы не загружать один и тот же ролик при каждом показе.

### 7.1. Автовыбор модели

В стандартном режиме роутер выбирает модель по задаче и доступности:

| Задача | Предпочтение |
|---|---|
| Универсальное text/image-to-video, длинные социальные сцены | Seedance |
| Нативный звук, речь, диалог | Veo |
| Сложное движение камеры, product/cinematic | Runway |
| Люди, выразительное движение, совместимый lip-sync поток | Kling |
| Говорящий аватар | HeyGen/действующий avatar-провайдер |
| Сцены без людей в совместимом сценарии | Sora |
| Музыка/песня | Suno |

Это приоритеты, а не жёсткая привязка. Роутер проверяет здоровье провайдера, доступный endpoint, входные ограничения, цену и пользовательский тариф. При недоступности предпочтительной модели показывает замену и новую цену до запуска.

### 7.2. Режим опытного пользователя

`🧠 Выбрать модель` и `🎛 Режим режиссёра` открывают текущие прямые генераторы и расширенные настройки. Глобальный переключатель «обычный/Pro» не добавляется: он заставляет пользователя принимать техническое решение до выбора задачи. Профессиональный режим доступен там, где он нужен.

## 12. «Свой запрос»

`📝 Свой запрос` оставляет свободный путь к многофункциональному GPT-чату. Перед входом бот показывает примеры и кнопку возврата в каталог. Свободный запрос не должен перехватывать текст, предназначенный для активного мастера, игры или производства.

## 13. Архитектура

### 13.1. Единый источник меню

Новые определения не добавляются третьим набором функций в `main.py`. Создаётся отдельный модуль, например:

- `neyrobot_prod/entertainment/catalog.py` — разделы, кнопки, доступность и порядок;
- `neyrobot_prod/entertainment/keyboards.py` — построение клавиатур;
- `neyrobot_prod/entertainment/router.py` — callback-роутинг;
- `neyrobot_prod/entertainment/flows/` — production, trends, games, leisure;
- `neyrobot_prod/entertainment/pricing.py` — расчёт и проверка цены;
- `tests/test_entertainment_*.py` — тесты меню и маршрутов.

В `main.py` остаются регистрация обработчиков и совместимые адаптеры к существующим функциям.

### 13.2. Пространства callback

Новые callback-data используют изолированные префиксы:

- `ent:` — корень и общая навигация;
- `np:` — Нейро Продакшен;
- `trend:` — трендовые рецепты;
- `game:` — игры;
- `leisure:` — досуг.

Старые callback-data продолжают обрабатываться. Для удалённых из интерфейса дублей сохраняются alias/redirect к каноническому сценарию.

### 13.3. Состояния

Состояние каждого мастера имеет namespace и версию: `ent.v1.*`, `np.v1.*`, `game.v1.*`, `leisure.v1.*`. При каждом входе валидируется ожидаемый шаг. Кнопки `Отмена` и `Назад` очищают только состояние текущего сценария, не удаляя чат и оплаченные результаты.

### 13.4. Каталог возможностей

Каждая карточка услуги содержит:

- стабильный `service_id`;
- пользовательское название и описание;
- callback;
- feature flag;
- обязательные входные материалы;
- поддерживаемые форматы;
- ценовой профиль;
- маршрут провайдеров и fallback;
- demo `file_id`;
- статус `active / beta / soon / hidden`;
- аналитику: событие показа, начала, оплаты, успеха и повтора.

Такой каталог становится единым источником для Telegram, будущего сайта и Mini App.

## 14. Кредиты, цена и защита маржи

1 кредит равен 1 ₽ для пользователя.

До запуска показываются: итоговая цена, состав результата, длительность/количество, возможные ограничения. Кнопка запуска содержит цену: `Создать за N кредитов`.

Правила расчёта:

1. Внутренняя себестоимость берётся из актуального каталога провайдеров.
2. Добавляются валютный буфер и резерв технических повторов.
3. Розничная цена не может быть ниже настроенного порога валовой маржи.
4. Если тариф провайдера неизвестен или устарел, платная генерация блокируется, а не запускается по приблизительной цене.
5. Для пакетного продукта цена считается по всем этапам до подтверждения.
6. Бесплатные демо ограничиваются отдельным бюджетом и квотой.

Транзакция:

1. Под блокировкой проверяется доступный баланс.
2. До вызова провайдера создаётся резерв на полную цену.
3. Повторное нажатие с тем же idempotency key не создаёт второй резерв и второй заказ.
4. После подтверждённой доставки результат фиксируется, резерв превращается в списание.
5. При ошибке/таймауте без результата резерв освобождается.
6. Баланс вычисляется как `ledger balance - active reservations` и никогда не может стать отрицательным.
7. Отрицательное изменение отклоняется на уровне БД, а не только интерфейса.
8. Каждый заказ хранит снимок цены, провайдера, себестоимости и версии тарифа для сверки маржи.

Рекомендуемая исходная политика: минимум 40% плановой валовой маржи после 15% буфера на курс и повторные обращения к провайдеру. Значения конфигурируемы; изменение не требует правки меню.

## 15. Видеопримеры и описание сервисов

Для каждого ключевого продукта готовится короткий ролик 6–15 секунд:

- первые 1–2 секунды — результат и сильный хук;
- затем исходник → процесс → результат;
- один ролик демонстрирует одну функцию;
- без длинной заставки и списка моделей;
- финальный кадр содержит действие: `Попробовать`.

В карточке Telegram: один демонстрационный ролик, описание в 2–4 строки, требования, цена/диапазон и кнопки `Попробовать`, `Другой пример`, `Назад`. На сайте используется тот же `service_id` и медиакаталог.

## 16. Совместимость и запуск

Вводится feature flag `ENTERTAINMENT_MENU_V2`.

1. Код разворачивается с выключенным флагом.
2. Новый интерфейс включается для тестовых Telegram user_id.
3. Проверяются возврат, оплата, повторные нажатия и незавершённые старые диалоги.
4. Включается ограниченный процент аудитории.
5. После проверки метрик — вся аудитория.
6. Старые callback-обработчики и команды сохраняются минимум один релизный цикл после полного включения.

При выключении флага пользователь получает текущее меню; данные и оплаченные заказы не теряются.

## 18. Проверки

Обязательные автоматические проверки:

- snapshot дерева и порядка кнопок;
- уникальность пользовательских названий и callback-data;
- каждый `active` service_id имеет рабочий обработчик;
- каждый `soon` service_id не может создать платный заказ;
- старые callback-data ведут в совместимый сценарий;
- изоляция состояний мастеров, игр и свободного чата;
- `Назад`, `Отмена` и повторный вход на каждом шаге;
- idempotency двойного нажатия;
- недостаточный баланс;
- резерв → commit на успехе;
- резерв → release на ошибке и таймауте;
- запрет отрицательного баланса на уровне БД;
- fallback модели требует повторного подтверждения новой цены;
- smoke-тест действующих Sora/Kling/Veo/Seedance/Runway/image/music потоков;
- отображение длинных русских подписей в Telegram Android/iOS;
- выключенный feature flag полностью возвращает старое меню.

Ручная приёмка выполняется на тестовом пользователе с реальными провайдерами и минимальными длительностями.

## 19. Метрики

Минимальный набор событий:

- показ раздела и карточки;
- начало мастера;
- завершение каждого шага;
- показ цены;
- отказ на цене;
- успешная оплата;
- успешная/ошибочная генерация;
- повтор результата;
- выбор ручной модели;
- возврат в меню.

Главные продуктовые метрики: доля начавших сценарий, завершение брифа, конверсия после цены, себестоимость успешного результата, валовая маржа, повторная генерация, возврат на 7/30 день.

## 20. Критерии готовности

Изменение считается готовым к общему включению, когда:

1. Корневое меню и все старые команды работают без регрессий.
2. В `Развлечениях` нет двух кнопок с одинаковым смыслом.
3. Все активные кнопки приводят к рабочему результату; заглушки явно помечены `Скоро`.
4. Стандартному пользователю не нужно выбирать нейросеть.
5. Опытный пользователь может открыть модель и параметры вручную.
6. Цена видна до подтверждения, двойной клик не списывает дважды.
7. Баланс не уходит ниже нуля при параллельных запросах и ошибках.
8. Фактическая себестоимость и маржа записываются по каждому платному заказу.
9. Есть минимум по одному проверенному демо для пяти главных продуктов.
10. Новый интерфейс можно мгновенно отключить feature flag без потери данных.
